# Custom client builder (planned, not scheduled)

Stage 1 shipped as **Install client** ([install-client.md](../install-client.md)):
the official RustDesk clients set up for this server, no builds. This document keeps
the plan for stage 2: branded clients (own name, icon, locked settings) built
from the panel. Not started; pick it up when there is demand.

## Prior art

- [rdgen](https://github.com/bryangerlach/rdgen) (GPL-3.0): Django UI that dispatches
  GitHub Actions in the admin's fork, patches `rustdesk` sources with `sed`, deletes
  the `custom.txt` signature check, builds Windows/macOS/Linux/Android (30–45 min).
  Problems: forks of public repos are public (logs, artifacts), no auth on its
  endpoints, silent `sed` misses ship RustDesk's default server, the permanent
  password sits in every installer.
- [DVForge](https://github.com/VenimK/DVForge) (GPL-3.0): rdgen's patches built on the
  admin's own machines (tens of GB of toolchains, one host per OS) plus a shared-token
  build farm. Has macOS notarization and per-version toolchain profiles worth reusing.

## Plan

1. **Builder repo** `rdpanel-client-builder` (separate, GPL/AGPL-compatible, public
   source as RustDesk's AGPL requires for modified clients). Admins create a
   **private** repository from it with "Use this template" (not a fork, so logs and
   artifacts stay private) and give the panel a fine-grained token with Actions
   read/write on that repository only.
2. **Panel wizard**: name, icon, platforms, permissions and locked settings. Server,
   key and API come from the panel. The panel dispatches the workflow with a build id,
   shows progress and fetches the artifacts through the GitHub API (no public panel
   URL needed).
3. **Signed settings instead of a removed check**: the fork replaces RustDesk's
   `custom.txt` verification key with the panel's own Ed25519 key, and the panel signs
   each profile's `custom.txt`. Settings stay tamper-proof; changing them later needs
   only re-packaging, not a full rebuild.
4. **Fail loudly**: after patching, the build verifies the server/key/app name made it
   into the sources; RustDesk tag and toolchain versions are pinned per profile;
   actions pinned by SHA.
5. **Signing hooks**: Windows code signing (PFX or a remote signer), macOS Developer ID
   and notarization, an Android keystore generated by the panel. Without them
   SmartScreen and Gatekeeper warn.
6. **Permanent password**: off by default, opt-in with a warning (anyone with the
   installer can read it); prefer the panel's access rules and "remember in account".
7. Order: Windows and Linux, then Android, then macOS.

## Open questions

- Private repository from the template (recommended) or public?
- Windows code signing certificate and Apple Developer account available?
- Allow a baked-in permanent password at all?
- GitHub Actions minutes: private repos on the free plan get 2000 min/month
  (Windows counts 2×, macOS 10×), roughly 20 Windows builds a month.
